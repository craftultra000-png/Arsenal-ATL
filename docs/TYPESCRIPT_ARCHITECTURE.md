# معمارية Arsenal ATL الجديدة — TypeScript متعدد الصفحات

## القرار المعماري

ستتحول المنصة من واجهة تشغيل واحدة تعتمد على iframe وحقن ملفات في وقت التشغيل إلى **تطبيق ثابت متعدد الصفحات (MPA)** مبني بـ **Vite + TypeScript**. ستكون لكل أداة صفحة فعلية مستقلة عند رابط دائم، ونقطة دخول TypeScript خاصة بها، وحزمة واجهة محلية خاصة بها. لا يوجد مسار تشغيل يمر عبر `toolLoader.js`، ولا توجد أداة تعتمد على DOM صفحة رئيسية أو نافذة أب أو iframe.

> مشاركة ملفات التصميم أو أدوات مساعدة TypeScript في وقت البناء لا تعني اعتماداً تشغيلياً. كل صفحة تُبنى كملف ثابت جاهز، ولا تحتاج إلى محمّل مركزي وقت تشغيل.

## قواعد الاستقلال

| القاعدة | التطبيق العملي |
|---|---|
| رابط مستقل | كل أداة تبنى في `/tools/<slug>/index.html` وتفتح مباشرة بلا وسيط. |
| نقطة دخول مستقلة | كل أداة تملك `main.ts` خاصاً بها ولا تستورد كود أداة أخرى. |
| لا iframe | تعرض الصفحة واجهتها مباشرة داخل DOM الخاص بها. |
| لا حقن | تستورد الصفحة CSS وTypeScript بصورة معلنة وقت البناء فقط. |
| حدود أخطاء محلية | أخطاء FFmpeg أو ONNX أو PDF تظهر داخل بطاقة الأداة نفسها. |
| تحميل عند الحاجة | أدوات الفيديو وحدها تطلب FFmpeg، وPDF وحدها تطلب PDF.js، والذكاء الاصطناعي وحده يطلب ONNX. |
| مصادر ثقيلة خارج الحزمة | ملفات WASM والنماذج الكبيرة لا تدخل Git أو Cloudflare؛ تُحمّل عند الحاجة من CDN مضبوط. |

## نظام الهوية البصرية

تشارك الأدوات طبقة تصميم صغيرة فقط. تتضمن المتغيرات الأساسية للون الخلفية الداكنة، الخط Tajawal، التموجات الهادئة، الهوية الفضية للشعار، أحجام الأزرار، والحالات المتجاوبة. لكل فئة متغير تمييز خاص بها يضاف إلى `ToolShell` من دون نسخ CSS عام:

| الفئة | اللون الفرعي | الهدف البصري |
|---|---|---|
| فيديو | أزرق كهربائي + فيروزي | معالجة وإنتاج |
| صوت | أخضر مائي | موجات وإشارات صوتية |
| صور | بنفسجي بارد | تحرير وطبقات |
| PDF | ذهبي هادئ | مستندات وإنتاجية |
| نصوص | أزرق نيلي | تركيز ووضوح |
| أدوات متعددة | فضي + تركوازي | مشاركة وأدوات عامة |

لا تفرض طبقة التصميم تخطيطاً ثابتاً على الأدوات. تشترك الأدوات في الترويسة والعودة ودعم RTL والوضع الداكن والخطوط ومكوّنات الإدخال الأساسية، بينما يبقى محتوى مساحة العمل والبطاقات والعناصر العملية خاصاً بكل أداة.

## التوجيه والفهرسة

سيكون لكل أداة عنوان ووصف وCanonical وOpen Graph وJSON-LD من `SoftwareApplication` داخل ملف HTML الخاص بها. المسار السابق `arsenal.html?tool=<id>` يتحول بتحويل دائم 301 إلى المسار الجديد في `/tools/<slug>/`. لن تُدرج صفحات تشغيل وسيطة في خريطة الموقع، لأن صفحات الأدوات النهائية هي الصفحات القابلة للفهرسة.

## البناء والنشر

يستخدم Vite مدخلات متعددة ليُخرج HTML ثابتاً لكل صفحة. لا يحتاج Cloudflare Pages إلى خادم أو SSR؛ يرسل مجلد `dist/` كما هو. تظل الأصول الصغيرة محلية، وتبقى الملفات الكبيرة خارج المستودع. يسمح ذلك ببيع ترخيص المصدر على نحو أوضح: يمكن فصل مجلد كل أداة أو ترخيصه دون كشف آلية تشغيل مركزية أو منطق أدوات أخرى.

## ترتيب التنفيذ

يبنى الأساس أولاً، ثم الصفحة الرئيسية ودليل الأدوات، ثم نموذج نقل كامل لضاغط الفيديو ومحول الصوت. بعد تأكيد النموذج، تنقل بقية الأدوات إلى نقاط دخول مستقلة مع المحافظة على وظائفها. لا يحذف المصدر القديم إلا بعد نجاح اختبارات كل رابط وكل تدفق إدخال ومعالجة وتصدير في النسخة الجديدة.
